# 显式事务

显式事务将多个查询组合为一个工作单元：开启事务，
在其中执行查询，然后提交或回滚。只读事务会固定
一个读视图并拒绝写入。读写事务会读取自身
成功的写入，并且仅在提交成功时才发布它们。

默认情况下，NeuG 在各自的自动提交事务中运行每个查询；仅当语句必须同时成功或失败时，
才将语句组合到显式事务中。有关事务模型、部署模式和自动提交行为，
请参阅[事务管理](transaction.mdx)；有关这些机制在内部是如何
实现的，请参阅[工作原理](how_it_works.md)。

|--------|----------------------------|------------------------|
| C++ | 是 | — |

| Node.js | 是 | — |

## 运行显式事务

### 嵌入式 AP 模式

在嵌入式模式下，显式事务由其 `Connection`.

<Tabs items={['Python', 'Node.js', 'C++']}>

<Tab>

```python
conn.begin_transaction()
created = conn.execute("CREATE (:Person {name: 'Alice'})", "insert")
visible = conn.execute("MATCH (p:Person) RETURN p.name")
conn.commit()
```

</Tab>

<Tab>

```javascript
conn.beginTransaction();

const created = conn.execute("CREATE (:Person {name: 'Alice'})", 'insert');
const visible = conn.execute('MATCH (p:Person) RETURN p.name', 'read');

conn.commit(); // Publishes all successful writes as one commit.
```

</Tab>

<Tab>

```cpp
auto status = conn->BeginTransaction(neug::TransactionMode::kReadWrite);
if (!status.ok()) {
  // Handle the begin error.
}

auto created = conn->Query("CREATE (:Person {name: 'Alice'})", "insert");
auto visible = conn->Query("MATCH (p:Person) RETURN p.name", "read");

status = conn->Commit();  // Publishes all successful writes as one commit.
```

</Tab>

</Tabs>

当客户端未指定模式时，默认为读写模式；每个客户端
还提供其 begin 调用的只读变体。有关确切的签名，请参阅
[Python](../reference/python_api/connection.md)、
[Node.js](../reference/nodejs_api/connection.md) 和
[C++](../reference/cpp_api/connection.md) 连接参考。

### 服务 TP 模式

在服务模式下，显式事务由其 `Session`，并且一个
`Session` 同一时间最多拥有一个事务。

<Tabs items={['Python', 'Java']}>

<Tab>

```python
from neug import Session

session = Session.open("http://localhost:10000", num_threads=1)
session.begin_transaction()
session.execute("CREATE (:Person {name: 'Alice'})", "insert")
assert list(session.execute("MATCH (p:Person) RETURN p.name")) == [["Alice"]]
session.commit()
session.close()
```

</Tab>

<Tab>

```java
import com.alibaba.neug.driver.Driver;
import com.alibaba.neug.driver.GraphDatabase;
import com.alibaba.neug.driver.Session;
import com.alibaba.neug.driver.Transaction;

try (Driver driver = GraphDatabase.driver("http://localhost:10000");
        Session session = driver.session();
        Transaction txn = session.beginTransaction()) {
    txn.run("CREATE (:Person {name: 'Alice'})").close();
    txn.run("MATCH (p:Person) RETURN p.name").close();
    txn.commit();
}
```

</Tab>

</Tabs>

有关服务模式的事务控制，请参阅
[Python 会话参考](../reference/python_api/session.md)和
[Java 会话和事务 API](../reference/java_api/session.md)。

## 规则和限制

两种模式均不支持保存点和部分回滚。

### 显式事务中被拒绝的语句

在事务处于活动状态时，两种模式都会拒绝相同的语句类别：

| 被拒绝 | 具体说明 |
|----------|------------|
| 批量、文件和临时加载 | `COPY … FROM`, `COPY … TO`, `COPY TEMP`, `LOAD FROM` |
| 管理语句 | `CHECKPOINT`、`INSTALL` / `LOAD` / `UNINSTALL`的扩展 |
| 变更状态的过程调用 | `CALL`调用变更状态的过程，例如 `project_graph` 或 `drop_projected_graph`；只读的 `CALL` 是允许的 |

其他所有操作均被允许，包括读取、插入、更新、删除以及
常规 DDL（如 `CREATE NODE TABLE`, `ALTER`, `DROP`）以及索引创建。
被拒绝的语句与任何其他失败语句的表现相同：它会使
事务变为仅回滚状态。

### 失败与仅回滚状态

到达数据库后失败的语句会使其事务变为
**仅回滚**状态：它不能再提交，并且必须在
客户端发出另一个查询或开始另一个事务之前结束。此类
失败包括：

- 语义分析、语法或编译错误
- 执行失败
- 在只读事务中尝试写入
- 被上表拒绝的任何语句
- Cypher `BEGIN`, `COMMIT`，或 `ROLLBACK` 作为查询提交——这些是
  不受支持的；请改用客户端的事务控制方法

在语句到达数据库*之前*被客户端绑定拒绝的错误
不会更改事务。例如，Python 会拒绝无效的
`access_mode` 带有 `ValueError`，并且事务保持可用。嵌套的 begin
调用和无效的程序化控制调用会报告事务状态错误
而不会更改原本处于活动状态的事务。

### 嵌入式 AP 模式详情

- **并发。** 读写事务在其整个生命周期内独占 AP 访问权限：所有其他 AP 操作都会等待，直到它提交、回滚
  或其连接关闭。嵌入式 READ_WRITE 模式也仅允许一个公开的
  `Connection` 同时执行。
- **生命周期。** 没有超时限制。事务会保持打开状态，直到
  应用程序将其结束，并且在打开期间不会进行其他 AP 工作，因此请尽快
  结束它。
- **结束仅回滚事务。** 将其回滚，或关闭连接。
  在此之前，连接仍会报告存在活动事务。

### 服务 TP 模式详情

- **使用会话。** Python 会将活跃 `Session`
  路由到其事务中。在 Java 中，将每个事务语句通过
  `Transaction.run(...)`；直接 `Session.run(...)` 调用会被拒绝，直到
  该事务结束。两个客户端都允许每个 `Session` 最多一个显式事务，并且关闭会话会尝试将其回滚。切勿通过一个 `Session` 发出并发请求；每个客户端工作线程使用一个 `Session`。架构
  查找始终显示服务的已提交架构，而不是
  事务私有架构。
- **并发。** 读写事务持有 TP 更新租约。当它
  持有租约时，其他读写事务无法开始，普通的插入和
  更新会等待其完成；读取保持并发。成功的提交
  会追加并发布一个 WAL 提交。
- **生命周期。** 当绝对生命周期到期或在关闭期间，服务会回滚并移除事务。到期是延迟报告的：
  下一个事务请求返回 `410 Gone`，并且 `Session` 随后清除其
  本地句柄。关闭或网络故障后，本地状态可能已过时；
  请关闭会话。普通的语句失败会使事务
  变为仅回滚状态。
- **结束仅回滚事务。** 调用 `rollback()`（或 Java
  `Transaction.rollback()`）。如果 Python 事务已到期，该
  调用会引发 `RuntimeError`在 `410 Gone` 上，但会清除本地句柄。在 Java 中，
  被 `Transaction.run(...)` 拒绝的语句会使事务
  变为仅回滚状态，因此只允许 `rollback()`。如果网络在
  Java 提交或回滚时发生故障，最终结果未知；驱动程序不会
  重试，必须关闭并替换所属会话。
- **放弃的事务。** 从未完成的读写事务
  会保留更新租约，并延迟普通的 TP 写入，直到服务
  释放它。始终在成功和失败路径上结束它。
