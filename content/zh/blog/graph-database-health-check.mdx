在 GitHub 上挑选开源项目时，你首先会看什么？对大多数人来说，答案是 Star 数。但 Star 数真的能告诉你一个项目是否健康、是否值得长期依赖吗？

Ollama 在 GitHub 上拥有 **250K Stars**，是目前最热门的本地 LLM 工具。如果让你猜它的社区健康度排名，你会把它排在第几？

**答案：74 个项目中排名第 68，处于红色预警区。**

其月活跃用户从峰值 1,128 人降至仅 150 人。核心开发者从 102 人一度缩减至 13 人，人员留存得分仅为 **8.8**（满分 100）——几乎没有人留下。与此同时，同赛道的 vLLM Star 数还不到 Ollama 的一半，健康度却排名**第 7**，维护者得分达到 90.6，并连续四年实现人才正增长。

**一个拥有 250K Stars 的项目，健康度竟然不如一个只有 50K Stars 的项目？** 这并非孤例，而是我们在 74 个项目中反复发现的规律。Star 数衡量的是“有多少人路过”，而不是“有多少人留下”。

本研究中的所有图数据存储、查询与分析均由 [NeuG](https://github.com/alibaba/neug) 嵌入式图数据库提供支持。

## 为什么要做这项研究

究竟该如何衡量一个开源社区的健康度？Stars、Forks、提交频率——这些截面计数描述的是“发生了多少事情”，而不是“社区结构是否健康”。有些项目在 Star 和提交数据亮眼、月活跃用户超过 2,000 时看起来最为“繁荣”，两年后却跌至个位数。**截面计数从未对这些崩塌发出预警。**

**尤其在 AI 浪潮下，热度让判断变得更加困难。** 一个 LLM 仓库首月出现 60K 个事件、获得数万 Stars 时，所有截面指标都在高喊“爆发”——但三个月后，活跃度可能只剩两位数。热度制造出“一切都很好”的假象，却掩盖了协作网络正在瓦解的事实。

我们需要一种能够穿透热度的评估方法——不再追问“发生了多少事件”，而是追问**“协作网络的拓扑结构是否健康”。**

于是，我们把 GitHub 协作行为建模为一个**随时间演化的图网络**，从**维护者倦怠风险、新人融入路径、社区互动质量和人员流动趋势**四个维度，为 74 个具有代表性的开源项目做了一次“健康体检”。研究覆盖 AI/ML、编程语言、前端、云原生和大数据等 10 个赛道，时间横跨 2021–2025 年，共 60 个月。所有图数据存储和分析均由 **[NeuG](https://github.com/alibaba/neug)** 嵌入式图数据库驱动；其高性能分析引擎让我们得以在数千个月度图快照上批量执行 k-core 分解、BFS 最短路径和聚类系数计算。

## 五个可能出乎意料的发现

### 发现 1：Star 最多的项目往往并非最健康

![Star 数与健康度](/images/blog/graph-database-health-check/2026-03-06-github-stars-01.png)

Ollama（250K Stars，第 68 名）、Next.js（130K Stars，第 62 名）、React（230K Stars，第 48 名）——这些家喻户晓的项目，健康度都处于中下游。反倒是 Elasticsearch（第 4 名）、vLLM（第 7 名）和 DuckDB（第 37 名，社区氛围满分）这类“默默做事”的项目表现更好。

> 关键信号不是“有多少人来过”，而是“协作网络是否紧密、人才是否愿意留下”。

### 发现 2：LLM 模型仓库的得分普遍偏低

baichuan2（19.6）、deepseek-v3（33.7）、yi（28.5）、chatglm3（48.1）——LLM 赛道平均分仅为 **39.9**，6 个项目中有 5 个低于 50 分，在所有赛道中垫底。

数据中存在两个显著模式：

**1. “发布即巅峰”的指数衰减**：baichuan2 首月有 2,925 个事件，12 个月后仅剩 43 个；yi 在 9 个月内从 5,908 降至 239；deepseek-v3 在 13 个月内从峰值 61,174 暴跌至 309。**vLLM 这样的工具型项目则恰恰相反——从 3,574 稳步增长至 12,614，越用越活跃。**

![衰减曲线](/images/blog/graph-database-health-check/2026-03-06-github-stars-02.png)

**2. 核心团队几乎完全换血**：全部 6 个 LLM 仓库的初始核心开发者都**几乎全部流失并更替**。baichuan2 的核心贡献者从 41 人降至 2 人，chatglm3 从 20 人降至 2 人——而且留下的位置大多由新面孔接替。

一种可能的解释是：LLM 的 GitHub 仓库更像“模型发布页”，而非长期协作型社区项目。模型发布后，研发重点自然会转向其他方向，真正的社区生态（微调讨论、权重分发）则更多发生在 HuggingFace 等平台上。这也意味着，**首月的数万 Stars 和事件反映的是关注度，而非社区黏性**。做技术选型时，应当意识到热度与长期社区活跃度之间的差距。

### 发现 3：维护者健康度与人员流动是“双支柱”

在 74 个项目中，与总分相关性最高的两个维度是维护者健康度（r=0.817）和人员流动（r=0.755），新人友好度紧随其后（r=0.578）。**维护者状态良好 → 人才愿意留下 → 社区保持健康。**

### 发现 4：越靠近基础设施，社区越能抵抗周期波动

![各赛道得分](/images/blog/graph-database-health-check/2026-03-06-github-stars-04.png)

AI 生态呈现清晰的三级梯度：基础设施框架（PyTorch/Transformers，平均 59.7）> 应用编排层（LangChain/AutoGen，53.2）> 模型发布层（39.9）。基础设施有技术护城河保护；编排层则太容易被替代，热度一退，人群就随之散去。

### 发现 5：“虚假繁荣”存在数学特征——高事件量 + 低聚类系数

LangChain 的月活跃用户峰值为 2,022，月事件数峰值为 14,796；两年后，MAU 降至 173（↓91%）。AutoGen 的变化更加剧烈，从 328 人降至**2 人**（↓99.4%），协作网络的聚类系数也降至 **0.000**。当 Star 曲线看起来仍然不错、网络聚类系数却持续下降时，说明协作关系正在松散，值得警惕。

## 反直觉案例：三个意想不到的对比

### 1. Ollama vs vLLM：同一赛道的冰与火

![Ollama 与 vLLM 的 MAU 对比](/images/blog/graph-database-health-check/2026-03-06-github-stars-03.png)

两者都是 LLM 推理工具——前者面向个人用户（本地部署），后者面向企业（高吞吐推理）。

|               |           Ollama           |       vLLM       |
| :------------ | :------------------------: | :---------------: |
| GitHub Star   |           ~250K           |       ~50K       |
| **综合排名**  |     **第 68（36.8）**     | **第 7（76.5）** |
| 维护者健康度 |            34.0            |     **90.6**     |
| 人员流动   |          **8.8**          |       84.5       |
| 倦怠风险      |           高           |      健康      |
| MAU 峰值→低谷    |    1,128 → 150（-87%）    |   峰值 1,306   |
| 核心开发者    |  102 → 24（一度降至 13）  |   稳定在 15–30   |
| 人才趋势      | 2025 年 -9.6%，2026 年 **-83.3%** |  连续 4 年正增长  |

**Ollama 的挑战是什么？** 人员流动得分 8.8，说明贡献者留存不足。2023 年 +100% 的快速流入，到 2026 年演变为 -83.3% 的大规模流出。维护者健康度得分 34.0，反映出核心团队显著收缩，倦怠风险很高。

相比之下，vLLM 的维护得分为 90.6，长期维持着 15–30 人的稳定核心开发者队伍，并连续 4 年实现人才正增长（虽然增速正在放缓，但仍为正数）。这是“健康、可持续增长”的教科书式案例。

> **启示**：这是一个值得关注的**“热度与健康度错位”现象**——Star 数衡量“有多少人关注”，健康度衡量“有多少人持续参与”。一个项目可以拥有 250K Stars，却只有 24 名核心开发者；关注度越高，这种差距反而越容易被忽视。在 AI 赛道进行技术选型时，**我们建议检查 Star 增长率是否与核心贡献者增长率相匹配。**

### 2. OpenClaw vs AutoGPT：闪电崛起之后，是着陆还是坠落？

OpenClaw 仅凭 2 个月的数据就冲到**综合第 1（92.4 分）**。我们把它与另一个曾经“闪电崛起”的项目——2023 年的 AutoGPT——放在一起比较。

|                      | OpenClaw（2026） | AutoGPT（2023） |
| :------------------- | :--------------: | :-------------: |
| **爆发月事件数**     |     100,277     |     82,469     |
| **爆发月 MAU**       |      3,382      |      1,985      |
| **爆发月核心开发者** |        25        |       108       |
| **次月 MAU**         |  2,349（-30.5%）  |   849（-57%）   |

AutoGPT 的故事是一个**成功“着陆”**的案例。2023 年 4 月爆发（82K 个事件）后，其 MAU 次月从 1,985 降至 849（-57%），核心开发者也从 108 人暴跌至 14 人——但它没有消亡。2024–2025 年，其月事件数稳定在 3,000–6,000，人才流动从 -33% 的失血状态恢复到 +9.4% 和 +22.4% 的正增长。AutoGPT 用两年时间重建了一个规模更小但更健康的社区，目前排名第 22。

OpenClaw 如今也站在同一个十字路口。2 月的 100K 个事件和 3,382 MAU，是全部 74 个项目中最大的单月爆发。OpenClaw 还拥有 AutoGPT 当年不具备的特征：**AI Agents 深度嵌入开发工作流**。greptile-apps[bot] 和 openclaw-barnacle[bot] 等机器人始终位列核心贡献者前列——这种模式在传统项目中几乎不存在。然而，OpenClaw 的 3 月 MAU 降至 2,349，下降了 30.5%。历史上，AutoGPT 在类似规模的爆发后，MAU 曾下降 57%；OpenClaw 的降幅虽然较小，却也没有逃脱这一模式。

![命运轨迹](/images/blog/graph-database-health-check/2026-03-06-github-stars-05.png)

“爆发容易、持续难”的铁律并不会因为 AI Agents 而改变。在 74 个项目中，其他出现类似爆发的项目包括 Stable Diffusion WebUI（2022 年 10 月 MAU 峰值 1,834 → 到 2025 年底仅剩 30，接近停滞）和 LangChain（2023 年 9 月 MAU 峰值 2,022 → 到 2025 年仅剩 173，低功率运行）。前方有三条道路：

| 命运          | 代表项目      | 关键差异                                             |
| :------------ | :-------- | :--------------------------------------------------- |
| 成功着陆   | AutoGPT   | 下滑后重建核心团队，人才恢复正增长                   |
| 低功率运行 | LangChain | 规模收缩 91%，但协作结构仍在（聚类系数 0.15–0.27） |
| 接近停滞   | SD WebUI  | 由少数人维持，协作网络日渐稀疏                       |

> **OpenClaw 能否避开 SD WebUI 的命运，复制 AutoGPT 的“着陆”？** 关键在于未来 6 个月内，它能否把首月涌入的参与者转化为稳定的核心贡献者。

### 3. Next.js：热门前端框架，社区氛围仍需改善

| 维度        |     Next.js     |  对照：DuckDB  |
| :---------- | :-------------: | :-------------: |
| 社区氛围得分 | **21.7**（第 73） | **100.0**（第 1） |
| 毒性率      | 峰值 **17.68%** |    **0.0%**    |
| 综合排名    |   第 62（50.2）   |   第 37（64.5）   |

![Next.js 毒性率](/images/blog/graph-database-health-check/2026-03-06-github-stars-06.png)

Vercel 的旗舰项目 Next.js 拥有 130K+ Stars，其在前端生态中的地位无需赘述。但它的社区氛围得分只有 **21.7**（满分 100），在 74 个项目中排名倒数第二。

主要原因是**负面评论比例不断上升**。我们使用 ToxiCR 模型扫描了 Next.js 的 674 万条评论，发现其毒性率从 2022 年年中的约 2% 上升至 15%，并在 2025 年 4 月达到 **17.68%**——远高于 5% 的健康基线。

相比之下，DuckDB 的毒性率始终保持在 **0.0%**，社区氛围得分满分。DuckDB 每月只有 100–180 名活跃用户，但社区中几乎没有负面互动。这是一个“小而精”的技术驱动型社区——规模不大，协作质量却极高。

> **启示**：社区规模与社区质量是两个不同的维度。大型项目如果缺乏有效的社区管理，负面互动可能会影响贡献者的参与意愿，进而形成恶性循环。

## 方法一览：在时间序列协作图上做健康检查

我们基于 GitHub Archive 的完整事件数据，构建了三类月度图：

- **参与者—参与者协作图（Actor-Actor Collaboration Graph）**：开发者之间的 PR 合并、代码评审和 Issue 讨论关系，用于识别核心开发者并计算协作密度
- **参与者—仓库贡献图（Actor-Repo Contribution Graph）**：开发者到仓库的贡献关系，用于追踪跨项目人才流动
- **参与者—讨论参与图（Actor-Discussion Participation Graph）**：开发者对 Issue/PR 的参与关系，用于评估社区氛围

我们使用**加权度中心性、k-core 分解、BFS 最短路径和聚类系数**等拓扑指标，从这些图中提取月度时间序列，再对序列执行“长期趋势 + 波动稳定性”双层分析，综合得到四个维度的得分（每个维度权重均为 25%）。

| 维度 | 衡量内容 | 关键图指标 |
| :---------------- | :------------------- | :----------------------------------- |
| 维护者倦怠风险 | 核心维护者是否正在减少 | k-core 分解、聚类系数、Bus Factor |
| 新人友好度 | 新人能否进入核心圈层 | BFS 最短路径、核心不可达率 |
| 社区氛围 | 沟通质量与响应效率 | 毒性检测（ToxiCR）、响应时间、关闭率 |
| 人员流动 | 人才池正在扩大还是缩小 | 年度净增长率趋势 |

## 给不同读者的建议

**技术评估者**：采用 AI 应用层框架时，不要被 Star 数蒙蔽。应检查 **Issue 关闭率**和**核心贡献者人数**——如果核心维护者少于 3 人，或人员已连续 2 年净流出，就应评估替代方案。优先依赖基础设施层（PyTorch、Elasticsearch），而不是编排层（LangChain、AutoGen）。

**社区管理者**：从“吸引眼球”转向“筛选核心贡献者”。Elasticsearch 的逆周期增长证明，成熟项目的核心竞争力不在于拓宽漏斗入口，而在于**优化漏斗颈部**——让有能力的贡献者更顺畅地进入核心层。应关注人员流动趋势：持续 2–3 年的人才外流，比 Star 数下降更早发出预警。

**开源贡献者**：优先加入**网络聚类系数高、核心层稳定**的项目（PyTorch、Rust、Kubernetes）。在这些项目中建立的深度协作关系，穿越周期的能力远强于掌握任何单一应用层框架。
