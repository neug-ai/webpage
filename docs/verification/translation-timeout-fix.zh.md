## 原故障与模型因素

[运行 40246596390](https://github.com/neug-ai/webpage/actions/runs/40246596390) 的英语同步完成，但在 53 个翻译候选中的第 17 个 `data_io/index.md` 发生片段翻译超时。旧请求固定 120 秒，片段最终失败会阻止整批提交和游标推进；已完成翻译没有跨 runner 检查点。

实际配置为 DashScope `qwen3.7-plus`。原脚本未发送 `enable_thinking`。[官方文档](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)说明该型号默认开启思考，额外推理可能造成非流式响应长时间等待。因此默认思考是有依据的嫌疑因素，但原日志没有 reasoning token 或服务端耗时，不能断言它是唯一原因。

## 修复范围

- Qwen／阿里云端点默认显式关闭思考，其他提供方默认不发送该专有参数；可显式配置 auto/true/false。没有自动更换模型，也没有改仓库变量。
- 超时可配置，默认 180 秒；一层有限重试覆盖请求、JSON／键集合、数据库术语等验证。认证／配置 HTTP 错误立即失败；超时、429、暂时性服务错误和不合格输出最多尝试 3 次。Retry-After 等待有上限。
- Markdown 大段先拆成有界片段，再按 JSON 实际字符数分批，默认每批不超过 6000 字符。代码、绝对／相对链接目标和 Nextra 控制值受保护。
- 只有验证成功的批次原子写入检查点。缓存身份包括输入、端点、模型、思考参数及完整提示词／术语指南，命中仍重新验证；损坏或验证失败的缓存不能跳过检查。
- 请求日志记录文件／批次、模型、尝试次数、耗时、request ID 和可用 token 统计，不输出凭据或原文／模型回答正文。
- 后续工作流准备为先 restore 缓存，再翻译，失败后也 save 已完成批次；这是配置变更，本轮未运行 GitHub Actions。
- 同步游标仍只在全部翻译成功后推进；检查点不等于同步成功。
